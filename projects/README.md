One folder per project. Each project's README should answer, in plain language:

1. **The problem** — what's wrong or missing, and who it affects.
2. **Who it helps** — the real people or community on the other end.
3. **What I built** — a short, non-jargon description.
4. **The result / impact** — what actually changed. Numbers if you have them; honest
   words if you don't.
5. **What I learned** — technical *and* personal growth.

> Write each README so a curious person who has never written code could follow it and
> understand why the project matters.
